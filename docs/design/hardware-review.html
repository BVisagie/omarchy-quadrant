1. Clear group boundaries

Four quiet panels replace a continuous stream of labels. CPU comes first; other sensors retain their identities.

2. Readings before metadata

Charge and state sit together. Device IDs, full model names and explanations have a consistent home in Details.

3. Honest status display

Invalid readings, denied access and missing values stay visible. Colour signals data availability, not an invented health verdict.

Proposed implementation scope
  1. Apply a shared section header, row spacing and detail treatment to Hardware. Use the existing theme, typography and responsive column layout.
  2. Order known sensor families by a stable rule, with CPU first. Use friendly labels only for recognised drivers; preserve raw labels and owner identity for unknown or repeated devices. Do not move groups when values change.
  3. Start with CPU package temperature and the range of available core readings. Expand the original core labels on demand; keep missing or critical core counts visible in the collapsed summary. Preserve the user’s expanded state during the session.
  4. Put full battery identities and existing capacity/power fields in Details. Do not omit fields simply because this screenshot does not show them.
  5. Preserve pinning, unit conversion, GPU actions when present, missing/error states and scroll position. Keep detail state across live updates and resizing. D operates only on visible sections.
  6. Validate laptops, desktops without batteries, multiple NVMe devices, unavailable sensors, long names, large fonts and narrow panels before opening a follow-up PR.
